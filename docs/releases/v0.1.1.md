🦊 In *First Tail*, the fox took its post at the gate. For *Unbroken Thread*, we gave it a night-shift test. Start a download through Japan, then try to break the US listener while the bytes are still coming in.

**One request through the Japan listener on port `2288` delivered all 14,614,528 bytes. The connection stayed open through three rejected US saves and two accepted configuration changes. The sender and receiver produced the same SHA-256.**

### What happened on the wire

We ran HAProxy and sing-box in an isolated Linux container on an Ubuntu x86-64 VM. A local SOCKS upstream and download server made the byte stream repeatable. “US” and “Japan” identify the two configured pools in this test.

| Configuration submitted to the US pool | Management API result | Bytes received by Japan during the rejection check |
| --- | --- | ---: |
| VLESS Reality link missing its public key | HTTP 400 | 1,179,648 |
| Outbound JSON with a field rejected by the sing-box binary | HTTP 400 | 1,703,936 |
| US listener set to a port already in use | HTTP 400 | 2,490,368 |

After each rejection, the test checked that the US group still had its original port and node list, and that the same core configuration was serving traffic. Then it submitted **two valid saves concurrently**, one for the US group and one for Singapore. Both took effect. A fresh connection through Japan succeeded while the original download was still running.

The digest of the downloaded payload was `1e38cd96c7ac4cef4a3dba538eb1866e89e4b42bbb6cab9dd4f0e6c1b94471a5`. The regression test checks the request count, byte count, digest and final traffic counters on each run. [Read the test](https://github.com/touka2014/kitsunegate/blob/v0.1.1/scripts/test-isolation.mjs).

### What changed

- **Configuration saves** start the candidate cores and check their listeners before committing the change. A failed save returns an actionable error and keeps the active configuration. After a successful handoff, established streams can finish on the previous core.
- **Route selection** keeps a fixed listener on its chosen node. The built-in balancer rejects new connections when every eligible node is down.
- **HAProxy startup** lets HAProxy select a connection limit compatible with the container's file descriptor budget. The release regression runs with a hard limit of 65,536 descriptors.
- **Health checks** read HTTP status lines across packet boundaries. The default is a 2xx response, or exactly 204 for `/generate_204`. You can specify an expected status after each URL and test a draft without changing the saved health counters.
- **Traffic history** weights each rate by the interval it covers, splits samples across chart buckets and shows gaps where measurements are missing. Counters include traffic from connections that finish during a handoff.
- **Management and startup** use a private API socket behind authenticated Nginx in Docker. The readiness endpoint returns HTTP 503 when a proxy core exits. Deleting every group and restarting now gives you the empty configuration you saved.

We repeated the download test on Ubuntu with the 65,536-descriptor limit after the HAProxy startup fix. All three invalid saves returned HTTP 400 again. The single request delivered **14,286,848 bytes**, with matching SHA-256 `1942f5913235f87f743023f20f209fff4ed0c40407e5c4d337828ef9206fc1a2`.

### Upgrade

To pin this patch, set `KITSUNEGATE_IMAGE=ghcr.io/touka2014/kitsunegate:0.1.1` in your Compose `.env`, then run:

```bash
docker compose pull
docker compose up -d
```

The image supports `linux/amd64` and `linux/arm64`. Local development now also requires management credentials. Use the configured admin password, or on a fresh local start read the generated password from `data/.admin-password`.
