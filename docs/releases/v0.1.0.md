# The first tail is awake. 🦊

Somewhere between a sleepy proxy node and your next connection, a tiny fox is now standing watch.

**KitsuneGate v0.1.0 — First Tail** is the first public release of an HAProxy-powered control plane for resilient proxy pools. It gives multiple proxy outbounds a stable set of listener ports, continuously checks whether each route is actually usable, and moves traffic away from unhealthy nodes before they can ruin your night.

This is not a mock dashboard and it is not a pretty wrapper around a static config file. The data plane is real: **HAProxy** accepts production connections, **sing-box** speaks the outbound proxy protocols, and KitsuneGate coordinates health, policy, telemetry, configuration, and lifecycle management from one web interface.

## ✨ What First Tail can do

### One gate, many proxy pools

Create as many proxy groups as your server needs. Every group owns an independent listen address and port, so one installation can expose separate entrances for the United States, Japan, Singapore, specialized routes, or any topology you invent.

Each pool can use one of four routing personalities:

- **Load balancing** — distribute connections across healthy nodes using weighted least-connections, weighted round-robin, or weighted-random selection.
- **Failover** — prefer lower-priority-number nodes and fall back automatically when the active route crosses its failure threshold.
- **Lowest latency** — choose the fastest healthy route while respecting a configurable latency tolerance to avoid constant flapping.
- **Fixed node** — pin a listener to one explicitly selected outbound when deterministic routing matters more than automation.

### Health checks that travel the real path

Green dots should mean something. KitsuneGate gives every enabled node its own local sing-box SOCKS adapter and sends HTTP or HTTPS probes through that adapter, the selected proxy protocol, and the remote server.

You can configure:

- Multiple probe URLs
- Check interval and timeout
- Consecutive failure threshold
- Consecutive recovery threshold
- Latency switching tolerance

The detailed result includes the target URL, HTTP status, measured latency, error reason, consecutive success/failure counters, and resulting routing state. The same evidence appears in the health dashboard and runtime logs.

### Outbound creation without config-file archaeology

Nodes can be created and edited in three ways:

- A guided manual form for the common fields
- A sing-box or Xray/3x-ui-style outbound JSON object
- A standard share link

First Tail supports **VLESS, VMess, Shadowsocks, Trojan, Hysteria2, and SOCKS** outbounds, including common TLS, Reality, WebSocket, gRPC, HTTPUpgrade, and uTLS options where the protocol supports them.

Imported credentials are encrypted locally with **AES-256-GCM** before they enter SQLite. Share links shown by the API are masked, and the encryption key remains beside the local database rather than being baked into the image.

### Telemetry for people who distrust decorative charts

The overview reads live cumulative byte and connection counters from the active balancer and calculates rates from the actual interval between samples. Sampling can be tuned from **1 to 60 seconds**.

The dashboard includes:

- Current inbound and outbound throughput
- Per-listener speed, bytes, and active connections
- Healthy-node ratio and average probe latency
- Traffic history for 30 minutes, 1 hour, 6 hours, 12 hours, 24 hours, and 7 days
- Automatic bucket sizing for longer time ranges
- Configurable traffic retention

### Logs from the whole party

KitsuneGate stores and presents logs from:

- HAProxy
- sing-box
- The runtime manager
- The management API
- The Windows built-in balancer
- Configuration and health-check events

Filter by source or severity, search by node, port, or message text, and choose how many days logs should survive. The configured minimum level also controls what is retained in SQLite.

### A dashboard that speaks your language

The management UI defaults to English and currently includes:

- English
- Simplified Chinese
- Japanese
- French
- Korean

Language, sampling, log level, and retention settings are stored server-side and apply consistently across browsers.

## ⚙️ Under the hood

```text
Client connection
      │
      ▼
HAProxy frontend :GROUP_PORT
      │  health-aware policy
      ▼
Dedicated local sing-box SOCKS adapter
      │
      ▼
VLESS / VMess / SS / Trojan / Hysteria2 / SOCKS node
      │
      ▼
Internet, hopefully before the opening theme ends
```

- HAProxy exposes independent TCP frontends and reports live counters through its runtime statistics socket.
- sing-box receives one adapter inbound per enabled node and owns the actual outbound protocol stack.
- The Node.js control plane validates inputs, generates both runtime configurations, manages process reloads, executes probes, and records telemetry.
- SQLite stores groups, encrypted nodes, settings, events, logs, and traffic samples in one portable data directory.
- Nginx serves the production dashboard and protects management routes with HTTP Basic Authentication.
- Docker uses host networking so newly created listener ports work without rewriting the Compose file.

The container pins and verifies the sing-box archive checksum during its multi-stage build. GitHub Actions publishes a single manifest supporting both `linux/amd64` and `linux/arm64`, together with an SBOM and build provenance attestation.

## 🐳 Deploy in a few commands

```bash
git clone https://github.com/touka2014/kitsunegate.git
cd kitsunegate
cp .env.example .env
```

Set a strong `KITSUNEGATE_ADMIN_PASSWORD` in `.env`, then awaken the gate:

```bash
docker compose up -d
```

The published image is available as:

```text
ghcr.io/touka2014/kitsunegate:0.1.0
ghcr.io/touka2014/kitsunegate:0.1
ghcr.io/touka2014/kitsunegate:latest
```

Both `amd64` and `arm64` images are included in the same tags.

## 🧭 Before you open the gate

- Docker deployment currently targets a **Linux host** with Docker Compose v2 and host-network support.
- The management UI listens on port `8080`. Keep it behind a firewall, private network, VPN, or HTTPS reverse proxy.
- Example groups contain no usable subscription credentials. Bring your own authorized proxy nodes.
- Back up both the SQLite database and `.secret`; encrypted credentials require the matching key.
- Windows local development uses KitsuneGate's built-in TCP balancer, while Linux and Docker use HAProxy.
- Existing RelayDeck data is migrated automatically to the KitsuneGate database name, with legacy environment variables accepted during the transition.
